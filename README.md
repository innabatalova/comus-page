# comus-page

Адаптивная промо-страница акции **«Оставьте свой отзыв»** (Комус): за отзыв
о купленном товаре пользователю начисляется 30 ₽ на баланс телефона.

Статическая вёрстка без сборщиков, зависимостей и фреймворков — страница
открывается прямым запуском `index.html`.

---

## Вёрстка mobile-first

Это ключевой принцип проекта: **базовые стили описывают мобильную версию**,
а всё остальное наращивается медиазапросами `min-width` — от узкого экрана
к широкому, а не наоборот.

```css
/* База — мобильные: карточки в колонку */
.need__cards {
    display: flex;
    flex-direction: column;
    gap: .75rem;
}

/* От 768px — перестраиваем в ряд */
@media screen and (min-width: 768px) {
    .need__cards {
        flex-direction: row;
        justify-content: space-between;
        gap: 1.5rem;
    }
}
```

Как это выдержано по всему проекту:

| Приём | Реализация |
|---|---|
| Точки перехода | Только `min-width`: `768px` (планшет) → `1000px` (десктоп). `max-width` в CSS не используется вовсе |
| Порядок медиазапросов | Блоки идут по возрастанию ширины, чтобы каскад надстраивался естественно |
| Типографика | Мобильные токены (`--font-h1-mobile`, `--font-text-mobile`) — база; десктопные (`--font-h1`, `--font-h2`) подключаются от `768px` |
| Раскладка | По умолчанию `flex-direction: column`; на широких экранах переключается на `row` |
| Контейнер | Базово резиновый (`max-width: 87.2%`), от `1000px` фиксируется на `61.5rem` |
| Popup | На мобильных — шторка снизу (`align-items: flex-end`, скругление сверху, `translateY(100%)`); от `768px` — центрированное модальное окно |
| Изображения | В `<picture>` сначала объявлены лёгкие мобильные кропы (`img-1-mobile`), десктопные версии подключаются на широких экранах |
| Минимальная ширина | `body { min-width: 20rem }` — корректный рендер от 320px |

Обратная сторона подхода: атрибут `media` в `<source>` использует `max-width`,
поскольку `<picture>` выбирает **первый подошедший** источник, и мобильные
кропы должны стоять выше десктопных.

## Технологии

### HTML5

- Семантическая разметка: `<section>`, заголовки `<h2>`/`<h4>`, списки.
- **`<details>` / `<summary>`** — аккордеон FAQ полностью на нативных
  элементах, без JavaScript. Стандартный маркер скрыт через
  `list-style: none` и `::-webkit-details-marker`.
- **`<picture>` / `<source srcset>`** — адаптивные изображения:
  - формат: WebP с PNG-фолбэком (`type="image/webp"`);
  - плотность пикселей: `@2x` для Retina;
  - арт-дирекшен: отдельные мобильные кропы `*-mobile`.
- Ленивая загрузка и асинхронное декодирование: `loading="lazy"`,
  `decoding="async"`.
- Инлайновые SVG-иконки (стрелка аккордеона, иконки блока «Зачем нужны
  отзывы», крестик попапа) — без лишних сетевых запросов.
- Доступность: `lang="ru"`, осмысленные `alt`, `aria-label` на кнопке закрытия.
- Русская типографика: неразрывные пробелы `&nbsp;` после предлогов,
  союзов и частиц, между числом и единицей измерения, перед тире.

### CSS3

- **Кастомные свойства** (`:root` в `css/variables.css`) — цвета, шрифтовые
  шорткаты, типографические шкалы.
- **Flexbox** — основная раскладка секций и карточек.
- **CSS Grid** — точечно, для центрирования (`display: grid; place-items: center`).
- **`clip-path: path()`** — декоративная фигура-«полигон» в hero-блоке.
- **Transitions и `@keyframes`** — раскрытие FAQ (`fadeIn`), поворот стрелки,
  появление попапа.
- Шорткат `font` для применения токенов одной строкой.
- Относительные единицы `rem` и проценты вместо жёстких пикселей.
- Нормализация стилей — [normalize.css](https://github.com/necolas/normalize.css)
  (вендорный файл, не редактируется).

### Шрифты

Подключены через Google Fonts с `display=swap`:

- **Montserrat** — заголовки и акценты;
- **Fira Sans** — основной текст, кнопки, попап.

### JavaScript

Отдельного JS-файла нет. Единственная интерактивность вне CSS — открытие
и закрытие модального окна с условиями акции через инлайновые обработчики
`onclick`, переключающие класс `.popup--open`.

## Структура CSS

```
css/
├── normalize.css   — сброс/нормализация (вендорный, без изменений)
├── variables.css   — дизайн-токены + утилитарные классы начертаний
└── style.css       — стили страницы
```

Порядок подключения важен: `normalize` → `variables` → `style`.

### Единый порядок объявлений

Внутри каждого правила свойства идут по одной схеме — от «где элемент»
к «как он выглядит и как реагирует»:

1. **Позиционирование** — `position`, `top` / `right` / `bottom` / `left`, `z-index`
2. **Отображение и раскладка** — `display`, `flex-*`, `grid-*`, `gap`, `align-*`, `justify-*`
3. **Размеры и отступы** — `width`, `height`, `margin`, `padding`, `overflow`
4. **Типографика** — `font`, `color`, `text-*`, `list-style`, `word-break`
5. **Оформление** — `background`, `border`, `border-radius`, `box-shadow`, `opacity`, `clip-path`
6. **Поведение и анимация** — `transform`, `transition`, `animation`, `cursor`, `user-select`

Сам файл разбит на пронумерованные секции: базовые стили → контейнер →
типографика → блоки (`hero`, `instructions`, `cta`, `need`, `faq`, `popup`) →
медиазапросы `768px` → `1000px` → `@keyframes`.

### Псевдоклассы

Состояния объявляются в порядке **LVHA**: `:link` → `:visited` → `:hover` →
`:focus` → `:active`. `:active` идёт последним, чтобы нажатое состояние
перекрывало состояние фокуса, а не наоборот.

### Вендорные префиксы

Префиксная запись ставится **перед** стандартным свойством, чтобы в браузерах
с полной поддержкой выигрывала стандартная версия.

| Свойство | Префиксы | Зачем |
|---|---|---|
| `clip-path` | `-webkit-` | Safari / iOS Safari до 13.1 |
| `user-select` | `-webkit-`, `-moz-`, `-ms-` | Safari требует префикс и сейчас |
| `transform`, `transition`, `animation`, `@keyframes` | `-webkit-` | Старые WebKit-браузеры и Android Browser |
| `appearance` | `-webkit-` | Сброс нативного вида кнопки в iOS Safari |
| `tap-highlight-color` | `-webkit-` | Только префиксное свойство, стандарта нет |

Свойства, которым префиксы **не нужны** и потому не добавлены: `border-radius`,
`box-shadow`, `box-sizing`, `flex`, `grid`, `opacity` — поддерживаются целевыми
браузерами без префиксов. Расчёт на актуальные версии Chrome, Firefox, Safari,
Edge и мобильные браузеры; IE не поддерживается (в проекте используются
`gap`, `clip-path` и кастомные свойства).
